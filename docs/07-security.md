# 07 — Güvenlik Tasarımı: url-shortener

- Tarih: 2026-07-27 | Mod: AUTOPILOT | Profil: LITE
- Girdi: `docs/03-requirements.md`, `docs/05-architecture.md`
- Ürün özeti (tehdit yüzeyi): anonim (hesap YOK) URL kısaltıcı; `POST /api/shorten`, `GET /:code`, `GET /health`; `node:http` + `node:sqlite`; **sunucu kısaltılan URL'i ASLA fetch etmez** (yalnız 302 Location).

## Varlıklar ve veri sınıflandırma
| Veri | Sınıf | Nerede duruyor | Koruma |
|------|-------|----------------|--------|
| Hedef (uzun) URL | **Confidential** — kullanıcı sorgu dizesinde token/oturum anahtarı taşıyabilir; içerik "gizli olmayan ama listelenmemiş" varsayılır | `links.url` (SQLite, düz metin), `/data` volume | Şifreleme yok (risk kabulü RA-2); DB dosyası 0600 + non-root container; loglarda query/fragment redakte (SEC-11); listeleme/enumerasyon ucu YOK |
| Kısa kod (`code`) | **Public** ama *unlisted* — kodu bilen eşlemeyi görür (yetkilendirme yok) | `links.code` (PK), yanıt gövdesi, URL yolu | CSPRNG 62^7 (~3.5e12) tahmin-dayanıklı uzay (SEC-7); enumerasyonu yavaşlatan rate limit (SEC-4) |
| `created_at` | Internal | `links.created_at` | Dışarı sızdırılmaz (yanıtta yok) |
| İstemci IP | **PII** (KVKK/GDPR) | Yalnız bellekteki rate-limit sayacı + erişim logu | Logda tam IP YAZILMAZ (tuzlu hash / son oktet kırpma), sayaç TTL sonunda düşer (SEC-11) |
| `links.db` dosyası | Confidential (tüm eşlemelerin toplamı) | Docker named volume `/data` | Volume host'ta root'a ait, container non-root+read-only FS (yalnız `/data` yazılır); yedek alınırsa aynı sınıf |
| Yapılandırma (`DB_PATH`, `PORT`, `BASE_URL`) | Internal | Env | Repoda düz sır YOK; hata mesajında yol/env sızdırılmaz |
| Sır (API anahtarı, kimlik) | **Yok** (varlık envanterinde bilinçli boş) | — | Uygulama hiçbir kimlik bilgisi tutmaz → sır sızma yüzeyi minimum; bu invaryant korunur |

## Auth / Authz stratejisi
- **Kimlik doğrulama YOK ve bu bilinçli bir üründür** (FR-1..3: anonim ziyaretçi; hesap/oturum/parola/token yüzeyi hiç yaratılmaz → A07 sınıfı açıkların tamamı tasarımla elenir). Oturum, çerez, JWT, CSRF token **yoktur**; `POST /api/shorten` durumsuzdur ve çerez okumadığı için CSRF anlamsızdır (saldırganın kendi adına link üretmesinin değeri yok).
- **Yetkilendirme modeli:** "capability-by-URL" — kısa kodu bilen yönlendirmeyi kullanabilir. Kod **gizli anahtar değildir**; ürün sözleşmesi "unlisted, not secret" olarak dokümante edilir (README + API yanıtı dokümanı). Bu yüzden gizli içerik kısaltmak kullanıcı riskidir.
- **Kritik invaryant:** Listeleme (`GET /api/links`), silme, istatistik veya admin ucu **eklenmez**; eklenirse bu doküman yeniden açılır ve kimlik doğrulama zorunlu olur (SEC-15).
- `GET /health` kimliksizdir ama **yalnız** `{status:"ok"}` döner — sürüm, yol, DB durumu, satır sayısı sızdırmaz.

## Faz 9'a güvenlik gereksinimleri (implementasyon listesi)
- [ ] **SEC-1 — Girdi doğrulama (UrlValidator):** `new URL(input)` ile parse; şema allowlist `['http:','https:']` (diğer her şey → 400: `javascript:`, `data:`, `file:`, `ftp:`, `blob:`, `mailto:`, şemasız); `typeof input === 'string'`, `length ≤ 2048`, boş/whitespace red; **kontrol karakteri (`\r`, `\n`, `\t`, `\0`, U+0000–U+001F) içeren girdi red**; `hostname` boş olamaz. Test: her red vakası ayrı case, DB'ye satır yazılmadığı doğrulanır (FR-3/NFR-2).
- [ ] **SEC-2 — "Sunucu fetch etmez" invaryantı (A10):** Uygulama kodunda giden HTTP/DNS çağrısı yok (`fetch`, `http.request`, `https.get`, `dns.*` kullanılmaz). Test/lint: `src/` içinde bu sembollerin geçmediğini doğrulayan bir kontrol testi. Önizleme/metadata özelliği eklenmesi Faz 7'yi yeniden açar.
- [ ] **SEC-3 — Açık yönlendirme kontrolü:** Yönlendirme **anında** DB'den okunan URL yeniden doğrulanır (SEC-1 aynı fonksiyonu); doğrulamayı geçmezse 404 + hata logu (bozuk/kurcalanmış satır kullanıcıya yansıtılmaz). `Location` başlığına yalnız doğrulanmış mutlak URL yazılır; başlık değerinde CRLF imkânsız kılınır. 302 kullanılır (kalıcı önbelleklenen 301 değil).
- [ ] **SEC-4 — Rate limiting:** Bellekte token-bucket, anahtar = istemci IP. `POST /api/shorten`: 10 istek/dk (burst 20). `GET /:code`: 120 istek/dk (enumerasyon yavaşlatma). Aşımda `429` + `Retry-After`. IP kaynağı `socket.remoteAddress`; `X-Forwarded-For` **yalnız** `TRUST_PROXY=1` iken ve son proxy atlaması olarak okunur. Sayaçlar TTL ile temizlenir (bellek sızıntısı yok).
- [ ] **SEC-5 — İstek sertleştirme:** Gövde tavanı 4 KB (bayt sayarak; aşımda soketi kapat, `413`), `Content-Type: application/json` zorunlu (aksi `415`), `server.requestTimeout=5s` + `headersTimeout=5s` + `keepAliveTimeout` ayarlı (slowloris).
- [ ] **SEC-6 — SQL güvenliği:** Yalnız `prepare()` + bağlı parametre; sorgu dizesine hiçbir kullanıcı verisi birleştirilmez; `INSERT OR REPLACE`/`ON CONFLICT REPLACE` yasak (Faz 5 kararı). Test: kanonik injection payload'ı (`' OR 1=1--`, `x'); DROP TABLE links;--`) kod olarak aranınca 404 döner ve tablo ayakta kalır.
- [ ] **SEC-7 — Kod üretimi:** `crypto.randomBytes` + **rejection sampling** (modulo bias yok), base62 7 hane. `Math.random`, zaman damgası, sayaç veya URL türevi kod YASAK. Test: 100k üretimde alfabe dışı karakter yok + dağılım çarpık değil + tekrar oranı 0.
- [ ] **SEC-8 — Yanıt sertleştirme:** Tüm yanıtlarda `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cache-Control: no-store` (redirect ve API için). Hata gövdeleri **jenerik** (`{"error":"invalid_url"}` gibi kod + kısa mesaj); stack trace, SQLite hata metni, dosya yolu, env değeri ASLA istemciye gitmez. `Server` başlığı temizlenir.
- [ ] **SEC-9 — Rota/yol güvenliği:** Yönlendirme rotası `^/[0-9A-Za-z]{7}$` ile eşleşmezse 404; statik dosya sunumu ve dizin listeleme YOK; kullanıcı yolu hiçbir `fs` çağrısına geçmez; `..`, URL-encoded traversal, çift eğik çizgi otomatik olarak 404.
- [ ] **SEC-10 — Güvenli JSON alımı:** Yalnız `{ "url": string }` kabul edilir; fazladan alan yok sayılır/reddedilir; `__proto__`, `constructor`, `prototype` anahtarları içeren gövde 400 (prototype pollution); `JSON.parse` hatası 400 (500 değil).
- [ ] **SEC-11 — Loglama:** Yapısal tek-satır JSON; alanlar: `ts, method, route, code?, status, dur_ms, ip_hash, event`. **Hedef URL'in query ve fragment'i redakte** (`https://host/path?<redacted>`), tam IP yerine per-process tuzlu hash. Zorunlu olaylar: doğrulama reddi, 429, kod-üretimi retry tükenmesi (500), tüm 5xx, boot/DB hatası. Log değerlerinde `\r\n` kaçışlanır (log injection).
- [ ] **SEC-12 — Çalışma zamanı/deploy sertleştirmesi:** Container non-root (`USER node`), `read_only` rootfs + yalnız `/data` yazılabilir, DB dosyası `0600`; DB dizini yazılamıyorsa **fail-fast** (sessizce tmp'ye düşme yok); `NODE_ENV=production`; dışa yalnız `127.0.0.1:<host_port>` bağlanır (nginx önünde), HTTPS + HSTS proxy'de zorunlu; inspector portu kapalı.
- [ ] **SEC-13 — Tedarik zinciri invaryantı:** `package.json.dependencies` **boş** (yalnız stdlib) ve `private: true`; CI adımı bu invaryantı kırılırsa build'i kırar; Node temel imajı sabit sürümle pinlenir (`node:sqlite` deneysel).
- [ ] **SEC-14 — (Derinlemesine savunma) İç ağ hedef denylist'i:** Hostname bir IP literal ise loopback (`127.0.0.0/8`, `::1`), link-local (`169.254.0.0/16` — bulut metadata), özel aralıklar (`10/8`, `172.16/12`, `192.168/16`) ve `0.0.0.0` reddedilir (400). Sınır açıkça dokümante: DNS rebinding / iç isimleri kapsamaz — bu tam SSRF koruması DEĞİL, kurbanın tarayıcısına yönelen kaba istismarı azaltır.
- [ ] **SEC-15 — Yüzey invaryantı:** Listeleme/silme/istatistik/admin ucu eklenmez; `GET /health` yalnız `{status:"ok"}` döner (sürüm/yol/satır sayısı yok). Yeni uç eklenirse Faz 7 yeniden açılır ve kimlik doğrulama zorunlu değerlendirilir.
- [ ] **SEC-16 — Tehlikeli API yasağı:** `child_process`, `eval`, `new Function`, `vm`, dinamik `require(<değişken>)` kullanılmaz; kontrol testi `src/` üzerinde bunu doğrular.

| RA-3 | Ürün doğası gereği **açık yönlendiricidir**; üçüncü taraf sitelerin allowlist'lerinde kötüye kullanılabilir | Kısaltıcının işlevi budur; kapatmak ürünü ortadan kaldırır | Yalnız http/https (SEC-1), yönlendirme anında yeniden doğrulama (SEC-3), `no-referrer` + `no-store` (SEC-8), iç ağ denylist (SEC-14) |
