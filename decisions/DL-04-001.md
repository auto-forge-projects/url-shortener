# DL-04-001: Depolama = gömülü `node:sqlite` (tek dosya DB)

- Tarih: 2026-07-27
- Faz: 4 — Çözüm Analizi
- Mod: AUTOPILOT
- Karar: Kısa kod → URL eşlemeleri, dış bağımlılık gerektirmeyen gömülü SQL deposunda (`node:sqlite`, tek dosya) `links(code TEXT PRIMARY KEY, url TEXT NOT NULL, created_at INTEGER)` tablosunda tutulacak; erişim `LinkStore { get, put }` arayüzü arkasından yapılacak.
- Değerlendirilen alternatifler: (A) Bellek-içi Map + periyodik JSON snapshot; (C) Append-only JSONL + bellek indeksi.
- Gerekçe: NFR-4 (çakışma 0) `PRIMARY KEY` ile veri katmanında zorlanır — uygulama hatası benzersizlik testini geçemez. NFR-3 için commit'lenmiş kayıt kalıcıdır; A'da snapshot penceresinde çöküş eşleme kaybettiği için FR-1'in "kalıcı depo" şartını karşılamaz. C kalıcıdır ama benzersizliği yalnız uygulama koduna bırakır ve kısmi satır/boot replay için daha fazla kod ister. NFR-1 (≤200ms p95) üç seçenekte de rahat karşılanır, bu yüzden ayırt edici değildir. Dış paket yok → Faz 9 sıfır-bağımlılık hedefi korunur.
- Riskler: (1) `node:sqlite` Node 22'de deneysel — API değişebilir/ExperimentalWarning basar; Faz 9'da sürüm sabitlenir ve tek adaptör dosyasında izole edilir. (2) DB dosyası container'da kalıcı volume gerektirir; Faz 12'de deploy config'e yazılacak, unutulursa restart'ta veri kaybı olur.
- Geri alınabilirlik: Yüksek (SQL yalnız tek `LinkStore` adaptöründe; alternatif C'ye geçiş ~1 saat, veri `SELECT *` ile taşınır — şema 3 kolon)
- İnsan onayı: Otomatik
- Varsayım mı?: Evet — AUTOPILOT varsayımı: çalıştırma ortamı Node ≥22.5 (fabrika ön koşuluyla aynı) ve kalıcı volume mevcut; ikisi Faz 12'de doğrulanacak.
