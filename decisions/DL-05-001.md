# DL-05-001: Katmanlı modüler monolit + LinkStore port/adaptör sınırı

- Tarih: 2026-07-27
- Faz: 5 — Mimari Tasarım
- Mod: AUTOPILOT
- Karar: Uygulama tek süreçli monolit olarak, `handler → LinkService → LinkStore portu → SqliteLinkStore adaptörü` katmanlarıyla kurulur. HTTP tipleri servise, SQL adaptörün dışına sızmaz; doğrulama (`UrlValidator`) ve kod üretimi (`CodeGenerator`) ayrı saf modüllerdir.
- Değerlendirilen alternatifler: (a) tek dosya script (router+SQL+validasyon iç içe), (b) mikroservis ayrımı (shorten/redirect ayrı süreç).
- Gerekçe: (a) Faz 4'ün "kilitlenme riski düşük" gerekçesi tam olarak port sınırına dayanıyordu — tek dosyada SQL her yere yayılır, adaptör değiştirme (JSONL'e dönüş) saatler yerine yeniden yazım olur; ayrıca saf modüller olmadan NFR-1 (süre) ve NFR-4 (benzersizlik) birim testle izole ölçülemez. (b) LITE profili + tek container hedefinde ağ atlaması ekleyip NFR-1 bütçesini boşuna harcar, operasyon yüzeyini büyütür.
- Riskler: Küçük üründe katman sayısı fazla gelebilir (aşırı mühendislik) → 4 modül + 1 adaptörle sınırlı tutuldu, ek soyutlama (repository factory, DI container) YASAK. Port sızıntısı riski Faz 10 review checklist'inde denetlenir.
- Geri alınabilirlik: Yüksek (depo değişimi tek adaptör dosyası; katmanları düzleştirmek geriye dönük veri etkisi taşımaz)
- İnsan onayı: Otomatik
- Varsayım mı?: Hayır
