# DL-07-001: Güvenlik duruşu — anonim tasarım + "sunucu fetch etmez" invaryantı

- Tarih: 2026-07-27
- Faz: 7 — Güvenlik Tasarımı
- Mod: AUTOPILOT
- Karar: Ürün kimlik doğrulamasız (anonim) kalır; güvenlik, kimlik yerine **yüzey daraltma + girdi doğrulama + hız sınırı** üzerine kurulur. İki invaryant çivilenir: (1) **sunucu kullanıcı URL'ini asla fetch etmez** (SSRF tasarımla elenir, SEC-2 testiyle korunur), (2) listeleme/silme/admin ucu eklenmez (SEC-15). Faz 9'a 16 test edilebilir SEC maddesi devredilir; sıfır runtime bağımlılığı güvenlik invaryantı sayılır (SEC-13).
- Değerlendirilen alternatifler: (a) API anahtarı/hesap ekleyip kısaltmayı kimliğe bağlamak; (b) kısaltma anında hedef URL'i sunucudan HEAD/GET ile doğrulamak ("ölü link ve zararlı içerik filtresi"); (c) URL itibar servisi (Safe Browsing) entegrasyonu.
- Gerekçe: (a) FR'lerdeki anonim ziyaretçi sözleşmesini bozar ve kimlik yüzeyi (parola/oturum/token) A07 sınıfı riskleri sıfırdan yaratır — bugün yüzey yok, en güçlü kontrol bu. (b) Doğrudan **SSRF açar** (iç ağ, bulut metadata 169.254.169.254) ve NFR-1 ≤200ms'i dış ağ gecikmesine bağımlı kılar — kazanç riskin yanında küçük. (c) Dış çağrı + API anahtarı = sıfır-bağımlılık ve "fetch yok" ilkelerinin ikisini birden bozar. Seçilen duruş MVP'yi hızlı tutarken en büyük açık sınıfını (SSRF, auth) tasarımla kapatır.
- Riskler: Anonimlik kötüye kullanımı açık kalır (RA-1, DL-07-002); "kod = capability" modeli kullanıcı gizli link kısaltırsa yanıltıcı olabilir → "unlisted ≠ secret" dokümantasyonu ve SEC-11 redaksiyonu ile izlenir; SEC-2 invaryantı ileride önizleme özelliği talebiyle sessizce kırılabilir → kontrol testi + Faz 7'yi yeniden açma şartı artefakta yazıldı.
- Geri alınabilirlik: Yüksek (kimlik/itibar kontrolü sonradan handler zincirine ayrı katman olarak eklenebilir; port/adaptör sınırı ve tek doğrulama kapısı bunu tek dosyaya sınırlar).
- İnsan onayı: Otomatik
- Varsayım mı?: Hayır (FR-1..3 + NFR-2'den doğrudan türedi)
